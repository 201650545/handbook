# handbook · 总规范仓库

> 跨项目的通用规范总库（SSOT）。所有项目仓库只写**项目特有**约束，通用规范一律引用本仓库——改一处，全局生效。
> 当前版本：**v1.0**（项目引用时必须写明版本，如 `handbook v1.0`，避免规则演进导致旧项目语义漂移）

## 规则优先级

```
项目明确 override > 项目自身规格 > handbook 默认规范
```

## 索引

- [10-协作规范.md](10-协作规范.md) — 人 / Agent / 外部模型分工，镜像站协作协议，执行纪律
- [20-出图与资产规范.md](20-出图与资产规范.md) — 出图规格、提示词锚点模板、命名与底图管理
- [30-台账格式.md](30-台账格式.md) — 任务看板与资产清单的统一格式
- [40-安全红线.md](40-安全红线.md) — 密钥、资产、隐私的红线清单（无例外）
- [templates/](templates/) — 新项目开工模板（README / project.yaml / 台账骨架）

## 三层职责（多仓 SSOT）

- **workspace-index**：有哪些项目、去哪找——只做索引，不保存任何正文副本
- **项目仓**：这个项目现在真实是什么——事实 + 对 handbook 的例外
- **handbook**：所有项目默认应该怎么做——不保存项目状态

## 用法

1. **外部协作者（AI）**：先读 workspace-index 定位项目 → 读项目 README 与 docs/00 总览 → 需要规范再查本仓库（注意项目声明的版本号）
2. **新项目开工**：从 `templates/` 复制骨架，docs 头部声明「继承 handbook v1.0，例外如下」

## 仓库管理

- 一项目一仓；main 单分支，文档改动即 commit，按里程碑推送
- 仓库内只有代码与文档；成品资产一律不进 git（见 40-安全红线）
